# Changelog

## [Unreleased] — post-v2.10.2

The multi-site layer: a project documents one building, and this is the floor above it — how the
buildings talk to each other (plan: `_local/notes/PIANO_multi-sede-wan-vpn.md`). Most of what
follows is the machinery under it; the last entry is the part you can see and use.

### Added

- **Sites and links: the multi-site layer is now something you can look at and fill in.** A new panel beside the project picker holds the organisation — its sites, their WAN uplinks, the tunnels between them — as a map and as a form, in the same place. They are not two features: a map nobody can populate stays empty forever, and a form with no map never shows what it is for. Writing it by hand is the *primary* path, not a fallback: the one-person IT department this is built for does not run NetBox, and the coming NetBox import will fill these same fields rather than different ones. Clicking a site on the map walks down into that site's own project. Reading is open to everyone and writing is admin-only, because documenting is not administering. Three things it refuses to do: it does not recompute the coherence audit, which already travels inside the server's answer — a second copy of that logic is how this codebase has grown a duplicate definition twelve times; after saving it adopts what the server actually *wrote* rather than what was sent, so a subnet coming back canonical or a link being refused is visible instead of silent; and a line that is not a network is named before saving rather than dropped afterwards. A measured value edited by hand becomes a declaration — that is manual-first — and the field says what it was beforehand, so nobody overwrites a reading without noticing.
- **The device that holds each end of a link — pickable from the site's project, or typed.** «Which box do I put my hands on» is the question you open this map at 3am to answer. The field suggests the devices of the site's project, WAN-edge kinds first — the firewall is the internet edge of a small business, the router is what you find when the line is carrier-managed — but nothing is filtered out, because somebody terminates a tunnel on a NAS and that is not ours to refuse. It is not a closed list: a carrier's CE is usually not a documented node and a site may not have a project yet, so forcing a choice from a list would have made the commonest case undocumentable. What you pick shows as linked and says when it stops resolving; what you type stays a declaration.
- **A site can take its networks from its project.** Instead of retyping what the site's project already says, one button adds them. It takes the *declared* networks — the rows of the project's Networks panel — and never the /24s inferred from device addresses: the first are a document, and copying a document into another document is honest; the second are a derivation, and promoting them to a company-level declaration would be inventing with the face of a choice. It only ever adds, never replaces, because there is no way to tell a hand-typed row from one taken yesterday, and a button that can delete somebody's work when mis-clicked is the wrong button. It reports two numbers — how many were added and how many the project declares — since «added 0 of 4» and «added 0 of 0» are different answers.
- **Where each site goes on the map is decided by a pure, deterministic module.** `lib/inter-site-layout.js` turns an organisation into coordinates: no SVG, no DOM, no strings — which is what lets the browser and the coming PDF / draw.io export draw *the same* map, because they read the same numbers. Same input, same coordinates, every time: no force-directed settling, because a map that rearranges itself on every open cannot be compared with yesterday's or printed twice alike. The shape follows the declared role — one declared hub goes to the centre, and zero hubs or two fall back to a ring rather than picking one for you. Two links between the same pair of sites (the real case: an MPLS primary with an IPsec backup) fan apart instead of drawing one line over the other. A link pointing at a site that does not exist cannot be drawn, so it is reported as undrawable with the missing name — a map that loses a tunnel in silence is worse than one that shows the hole.

- **A value can now carry how we know it.** `lib/provenance.js` is the envelope: a value is `declared` (a person wrote it — and it never ages, because a decision does not expire), `measured` (read from a device at a stated instant), or `derived` (computed, naming what from). A bare value is deliberately *not* promoted to `declared` for convenience, and a measurement whose timestamp cannot be read is never stamped with the current time — it stays `undated` and says so. It composes with `lib/source-ref.js` instead of repeating it: *which* external object a value came from is an identity question that already has a home, so there is no fourth `imported` origin. The four state engines that exist (`proof`, `temporal-confidence`, `identity-reconcile`, presence) are untouched; new facts are born with the envelope and the model converges forward. ⚠️ One thing the plan got wrong and the code does not: there is no single age rule to unify. `proof.js` (6h / 7d / 30d) measures how fresh the *proof that a device is alive* is; `temporal-confidence.js` (30d / 60d) measures confidence in a *repeated sighting*. Different questions, legitimately different half-lives — so what is shared is the shape of the answer, and the scale is a required argument with no silent default.
- **The model of the multi-site layer: an organisation above the per-site projects.** InfraNet documents one site per project and the projects are islands — nothing modelled the WAN uplinks and the site-to-site tunnels that actually hold a multi-site business together. `lib/inter-site.js` carries sites (each a *reference* to its existing project, never a copy), WAN uplinks, and inter-site links over one closed vocabulary — `ipsec`, `mpls`, `vpls`, `sdwan`, `directLink`. Which subnets a link makes reachable at each end is a single concept (`reach`) across every kind — on an IPsec link it *is* the encryption domain — so no vendor's word enters the model and no viewpoint-dependent «local/remote» either. The envelope sits only on what a device could actually report: a provider, a circuit ID or a contracted rate are declarations by construction (and the contracted rate is never `ifSpeed`). Subnets are canonicalised through `lib/cidr`, so the same network written two ways is one subnet. Model only — no view, no network, no diagnostics.
- **A TypeScript source can no longer be added under `lib/`, and the guard says why.** These modules were written as `.ts` first: Node strips types natively from 22.18 and esbuild compiles them for free, so they ran locally on Node 24. They would have broken CI. `package.json` declares `engines: node >=16` — this is self-hosted software that runs on other people's machines — and CI runs Node **18.x and 20.x**, where the CommonJS loader knows only `.js`, `.json` and `.node`: an unknown extension is handed to the `.js` handler, so a `.ts` file is read as JavaScript and its type annotations are a `SyntaxError`. Verifying that the tool works without checking *where it has to run* is exactly the mistake; `test/ts-gate.test.js` now fails on any `lib/*.ts` (`lib/types.d.ts`, an ambient declaration nobody requires, is the one legitimate exception), checks that `engines` still justifies the ban, and parses every `lib/*.js` the way Node 18 would. Nothing was lost but the extension: the types live as JSDoc `@typedef` — the shared ones in `lib/types.d.ts`, where the repo already keeps cross-module domain types — `tsc` checks them exactly as before, and a `.js` is additionally covered by ESLint and `npm run check`, which a `.ts` was not.

- **The multi-site model can now check itself, on the declared data alone.** `lib/inter-site-audit.js` answers the questions a hand-drawn multi-site document should have to survive: a tunnel that carries a network no site claims; the same subnet declared at two sites; an endpoint pointing at a site that does not exist; a spoke that touches no hub. Incoherences and gaps are kept apart — a tunnel carrying a network nobody owns is *wrong*, an uplink with no public IP is merely *unwritten*, and folding the two is how an audit starts crying wolf. Every check that could not run leaves its name and its reason in `notChecked`, the same discipline `lib/ipam-audit.js` already carries: an empty list must mean "I looked", never also "I didn't". ⚠️ Two corrections to the plan came out of building it. The "asymmetric encryption domain between the two ends" it called for is *not expressible* on this model and is said so rather than faked: `reach` is one declaration on the link, not two to compare — two ends that contradict each other only show up when both firewalls are read, which is drift. And the obvious check (a link's `reach` at one end must sit inside that site's own subnets) is deliberately absent: through a hub, a link legitimately carries a third site's networks, so that check would fire on every real hub-and-spoke.
- **The audit catches a link claiming to run on a line that cannot be its line.** Now that any kind of link can say which WAN lines carry it, that statement can be false in two ways, and both are contradictions between things somebody declared: the line belongs to a site that is neither end — a Turin line cannot carry a Milan-to-Rome link — or the line does not exist at all, deleted after the box was ticked. One list, with the site named, because the repair is the same in both cases: untick it. The panel already declines to *offer* a third site's lines, and that is not enough: the file gets written by hand, comes back from a backup, and a link's two ends can be changed *after* its lines were ticked — which is the case that actually happens, and nobody goes back to check. On paper it is invisible, and that is the worst place for it to be: the recovery card prints «provider · circuit id» with no site, so a wrong line reads exactly like a right one. A link with a broken end is deliberately left alone: it is already reported as pointing at a site that does not exist, and until that is fixed nobody can say which site the line should have belonged to — two rows for one fault make it look like two faults. ⚠️ And when no link declares any line at all, the check reports itself as **unable to look** rather than clean — which on a real archive is every link, and is how the audit says «this question exists and nothing has answered it» without accusing anyone of a defect.
- **The multi-site model is now stored, and the server is the one that decides what is well-formed.** `data/organization.json` holds one organisation per installation — this install of InfraNet is this company, with its sites — which is the shape of the 2-to-5-site business the layer exists for; the plan puts MSP multi-tenancy explicitly out of scope, and the day it is wanted this is the file to change, deliberately. It does NOT live inside a project: the organisation is shared across the per-site projects, and a copy in each would be, by construction, the same fact in two places. Sites point at their project with `projectRef` — a reference, never a copy. `GET /api/organization` is open like the project list and returns the organisation together with its coherence audit; `PUT` replaces it and is admin-only, like saving a project. The server re-normalises the body rather than trusting the client, and answers with what was actually WRITTEN plus a count of what was refused: a link with a `kind` outside the vocabulary must not enter, but if it vanished in silence the person who saved would believe they had saved it. The one check a browser cannot make itself — whether a site's `projectRef` points at a project that exists — is added by the route, and says so in `notChecked` when the project list cannot be read.
- **Every field of a project now has a written class.** `lib/project-schema.js` says, for each field of `state`/`node`/`spec`/`port`/`link`, whether it is a `document` (a person wrote it), a `measure` (a device reported it), `derived`, `private`, or a `secret` — and therefore what happens to it in an export. 165 fields, censused from thirteen real projects. For the older fields that can come from either a hand or a reading — `serialNumber`, `mac`, `model`, `ip` — the rule is that anything a person can type in the UI stays a `document`: getting it wrong towards `document` puts one extra field in an export the user made themselves, while getting it wrong towards `measure` **deletes somebody's work**, and the two mistakes are not equivalent. An unclassified field is kept for the same reason; what makes the gap loud is `test/project-schema.test.js`, which goes red when a field seen in a real project has no class.

- **From inside a site you can now see that you are inside one, and walk back up.** Clicking a site on the map already opened that site's project — but once you were in there nothing said where you had come from, and going back meant knowing that the toolbar button was the way. The sub-header's path now reads `InfraNet Pro / <organisation> / <project> / <view>`, and the organisation segment is the step back up. It appears only when a site *declares* this project (`site.projectRef`) and never by matching names, because two sites can be called like their projects and a path nobody stated is a path invented. The name of the loaded project stays the segment — it is the document actually open — and when the organisation calls that site something else, the declared name is in the tooltip rather than printed beside it: two names side by side are noise, and showing only one would be choosing for the user which of the two is true. This is the drill-down Packet Tracer does with its Physical Workspace bar, with one honest difference: there the levels are views over a single file, here they are two separate documents (a project per site, by design), so going up reopens the floor above instead of zooming out of it.
- **A site's box on the map says how much is inside it, before you go in.** «42 devices · 1 rack» under the networks, so the weight of a site is visible from the floor above and a site whose project is not linked yet reads as such at a glance. The numbers are counted by the server inside the parse it already does for the project list, so nothing extra is read — a floor plan travels as a data-URL and downloading whole projects to count them would have cost megabytes per open. ⚠️ They are `null`, never `0`, when a project has no readable state: a project saved by an older version is one whose contents we do not know, and «0 devices» would be a stopgap that nothing downstream can tell apart from a measurement — the box stays silent instead. The count uses the same structural denylist as the rest of the backend, and `test/layout-types-parity.test.js` now pins that denylist to the frontend catalogue it mirrors: the two lists were already duplicated on purpose, with the reason written down, but nothing was watching them — and this is the codebase where a definition split in two has diverged twelve times. Divergence would now be *visible and wrong*: the box would claim one number and the sub-header inside that same site another.
- **After an import, InfraNet offers to put the site on the map.** The import created a project and stopped there: whoever imported a site found the inter-site map still did not know about it, and nothing said the link had to be written by hand in the panel. The DCIM answer now carries the NetBox sites the project came from — the same ones already recorded in `state.source` — and the result screen offers to register it, with the name and the project reference already filled. It **offers**: joining the organisation is a company-level declaration, and an import that added itself to the map would be deciding that this project *is* a site on the user's behalf. Only what is known gets filled — the name (NetBox says it) and the reference (a fact); the networks keep their own dedicated action rather than being guessed here. Four of the five outcomes deliberately have no button: a project already registered says so; a namesake site with no project is *linked* rather than duplicated; a namesake pointing at a different project is left alone, because that is somebody's declared work; and a project born from **more than one** NetBox site is refused with the reason — one site is one project, so two sites sharing one project would be a false statement and picking one would be worse. Measured on a real NetBox: importing with no scope pulled in twenty sites, so that list is truncated after three names and counted.
- **What LINKS two sites is read too, not just what each one buys.** NetBox keeps L2 services and tunnels in an application of its own — `vpn/` — which is neither the DCIM nor the circuits, and which nothing was reading: a VPLS between two branches, an IPsec to the datacentre, a GRE to the lab all stayed behind. They arrive now, alongside the circuits, in the same per-site read.
  Here the *kind* IS deduced, and the difference from the circuits is not a matter of convenience. A circuit's type is free text of that instance («MPLS», «Fibra spenta»), so a link born from one enters as `other`; but `l2vpn.type` and `tunnel.encapsulation` are **closed vocabularies of NetBox** — `vpls` means VPLS in every installation on earth and `ipsec-tunnel` means IPsec. Translating one closed vocabulary into another is a translation, not a guess, and it stays vendor-neutral precisely because it never looks at what the user named things. Everything with no counterpart here — VXLAN, EVPN, GRE, WireGuard, E-Line — enters as `other` carrying NetBox's own label: the software knows that it does not know, and the name is not lost.
  ⚠️ **The outside addresses cross over.** In NetBox `outside_ip` is the external address *of that end*; in this model `peerIp` is the address of the *other* end — the one you type into the tunnel's configuration. Handing each end its own would be exactly backwards, and downstream nobody could tell: two plausible addresses in the two wrong fields. The roles say the shape when they say it — a `hub` and a `spoke` make `hub-and-spoke`; two `peer`s do **not** make a mesh, because "mesh" is a statement about the whole set and two ends cannot support it.
  A multipoint service (three sites on one VPLS) is refused with the reason rather than split into pairs — the same rule that keeps an MPLS cloud a set of uplinks. Only what is *active* is offered; a `disabled` tunnel does **not** become "state: down", because disabled-in-the-document is a decision and `down` is a measurement, and the two would read the same. The identifier (VNI / VC-ID) has no field here and is *said* rather than tucked into one that would start to lie.
  ⚠️ And a measured surprise: NetBox **accepts `?site_id=` on `vpn/` and ignores it** — on 4.6.7 the filtered and the unfiltered call return the identical list. The scope is therefore done entirely by the belt that re-checks every row, and the mock in the bench had to be made *worse* to match: it filtered properly, which meant it was testing something the real server cannot do.
- **The WAN lines of a site can now be read from NetBox, instead of only typed by hand.** NetBox models the lines that leave a building as **circuits**, in an application of its own that the import never opened at all — so a site could be imported perfectly and still arrive with zero uplinks, and the inter-site map looked stuck on whatever had been entered before. A button on each site reads them: it **adds**, never replaces, exactly like the button that takes the networks from the project, because there is no way to tell a row typed yesterday from one taken from the DCIM and a button that replaces a list is a button that deletes somebody's work when pressed by mistake. The scope is not chosen by whoever is looking: it comes from the site's project, which records the NetBox site it was born from (`state.source.dcim.sites`) — a project written by hand has none, and then there is nothing to ask rather than all of NetBox to read and pretend it is about this site.
  Four decisions decide what a circuit becomes, and each one is a case the data actually contains — measured on a real NetBox 4.6.7 with **29 circuits**, which map to **26 uplinks and 3 links, with nothing lost**. One end at a site and the other anywhere else is an **uplink**; two ends at two different sites is an inter-site **link**. A line whose far end is a carrier's **provider network** (13 of the 29) stays an uplink and the cloud is *said* rather than modelled: several sites on one MPLS cloud are not pairs of connected sites, and turning them into adjacencies would invent N·(N−1)/2 links nobody declared. The **kind** of an inter-site link is never guessed from the circuit type, which is free text of that instance («MPLS», «Dark Fiber», but equally «fibra spenta»): matching it by string would work on that one archive and no other, so the link enters as `other` carrying those words, and the dropdown stays with whoever knows. And a circuit that is not **active** is not offered at all: an uplink has no state field, so importing a `planned` or `decommissioned` line would make it indistinguishable from one in service — they are listed with their status instead, and can be written by hand.
  What comes across is what NetBox can answer for: provider, circuit id, service type, and the committed rate — which NetBox keeps in **kbps** and is divided into Mbps. Beside it on the termination sits `port_speed`, and using it as a fallback when the commit rate is missing is the classic trap of this domain: that is the speed of the *port*, so it would write «100 Mbps guaranteed» across a best-effort line. It stays empty, and the panel says how many lines were left empty and why. The SLA reference and the public addresses are not filled either: the first does not exist in NetBox, and the second cannot be derived from the address of a WAN interface without guessing past NAT and routed blocks. The cable that leaves the circuit termination does identify the **WAN port** — device and interface — and on that real instance it resolved for **26 uplinks out of 26**; it is shown so the line can be recognised, and it is what fills the ends of an inter-site link, by name, so the panel's own rule turns it into a reference only when it matches exactly one device of that site's project.
  Everything that could not be placed is said in the panel rather than dropped: a circuit going to a site this organisation does not hold, a line already there, a termination scoped to a region instead of a site, a read that was truncated. ⚠️ And the scope is re-checked row by row after NetBox answers, because NetBox **ignores a query filter it does not know and returns the whole archive** — measured: an invented filter came back with 29 circuits out of 29 — so without that belt the lines of every site would land on one.

- **The WAN goes into the PDF: the map of the sites, and what it takes to rebuild it after an incident.** A dossier described one building down to the outlet and said nothing about how that building reaches the others — so the one document you would carry to a site at 3am was missing the half you would need there. A new chapter, on by default in the report options and in the handover dossier, prints the inter-site map and then one recovery card per WAN line and per link: who sells it, the circuit id you dictate on the phone, the committed rate (never the port speed — that is the trap of this domain, and it would promise a guarantee nobody sold), the SLA reference, the WAN interface with when it was read, and the public addresses as a *list*, because one address is false as soon as there is a routed block, an IPv6 alongside it, or an HA pair. For a link it prints the kind, the state with who says so, the VRF or service or overlay, the IKE version, the device holding each end — resolved from that site's project, or typed, or *said* to be unresolvable, which are three different answers — the peer address ⚠️ which is the address of the **other** end as seen from here and is labelled that way, and the networks the link makes reachable at each end, which on an IPsec **are** the encryption domain: bring the tunnel back up without them and nothing passes through it.

  ⚠️ **The map is redrawn for paper, not exported from the screen.** The panel's SVG wears CSS classes and takes its colours from the stylesheet, which inside a PDF does not exist: handed to `svg-to-pdfkit` it would have come out as a sheet of black shapes — and since those classes follow the *theme*, a user working in dark mode would have handed their client light text on a white page. Here every colour is an attribute and the white ground is a declared rectangle, so the page prints the same for whoever generates it. It stays **vector**, never a raster: a dossier gets read zoomed to 400% on a laptop in a plant room. The coordinates come from the same pure module the panel uses (`lib/inter-site-layout.js`), so the printed map and the one on screen are the same map rather than two drawings that will drift apart — and the text is measured with **pdfkit itself**, which is the ruler that module asks for and the very engine that will draw it, so a box grows on the real width of the real name. Two smaller things learned on the page: the hub is marked with the *word*, because a standard PDF font does not substitute a glyph it lacks — it draws the wrong one, and the panel's ★ came out as a random symbol; and a link declared down is **dashed** as well as red, since red and green are the same grey in a black-and-white photocopy.

  Two choices are deliberate and go against the neighbouring chapter. Where a PDU card drops a field it has nothing for, a WAN card **keeps the four you telephone with and prints a dash**: a line with no circuit id is not a gap in the layout, it is the finding, and it has to be visible now rather than the night it is needed. And the header counts the chapter's own holes — lines with no circuit id or no provider, links with no declared networks, sites with no line — the way the recoverability chapter counts devices with no backup: a dossier that hides its own gaps is more dangerous than one that prints them. A link pointing at a site that no longer exists cannot be drawn, so it is printed anyway with the name of what is missing; an installation that never opened the multi-site panel gets the empty state rather than a chapter that silently disappears, which reads as a bug in the export.

  Like the power chapter, the rows are composed **in the server** — the organisation is one per installation and lives in `data/organization.json`, not inside the project, and `lib/inter-site*.js` in the browser lives only inside the ESM bundle where `export.js` cannot reach it. The client sends a ticked box; nothing else. One piece of housekeeping came with it: the XML escaper that the draw.io export kept to itself is now a shared module (`lib/xml-escape.js`), because the second XML format we emit would otherwise have started life as an identical copy of the first — which is precisely the duplicate definition this codebase has grown twelve times.

- **The WAN audit stops handing out clean bills of health it never earned.** An organisation carrying nine
  things a network engineer would reject on sight — a link declaring a WAN line at one end and nothing at
  the other, a tunnel that never says which line carries it, a link whose two ends are crossed so the peer
  address «seen from Milan» is Milan's own, a line claiming an MTU of 150000 — came out of the audit with
  *zero problems, zero gaps, zero unchecked*: a full acquittal. Four checks close that, and the one that
  fires hardest on a real archive is the plainest: **a link that does not say which WAN line carries it**.
  «The Milan fibre is down — what falls with it?» is the question the recovery chapter exists to answer,
  and on the first real organisation five links out of eight had no answer, with nothing saying so.
  A `directLink` is deliberately exempt: between two of your own buildings the emptiness is the *right*
  answer, because that link **is** the line, and asking would accuse half the real cases of a gap they do
  not have. Two of the four were **promises the model had already made in writing** — «an implausible MTU
  is the audit's business, which flags without destroying, not the normaliser's, which discards» — to a
  module that had never received anything: the model declined to discard *because* somebody else would
  flag, and that somebody was not looking. The thresholds signal rather than reject, and are set where
  they cannot be wrong later: below 1280 IPv6 cannot run on that link at all, above 9216 is past ordinary
  jumbo delivery (some platforms reach 9600, which is exactly why it is a flag and not a refusal), and
  beyond a terabit on a site access is almost always kbps typed into the Mbps field.
  ⚠️ **One guard that was asked for is deliberately not here, because it would refuse true archives.**
  «The same line cannot carry another technology» sounds right and is not: an internet line under three
  IPsec tunnels is the ordinary case — it is why that field is a list — and on the real archive one access
  legitimately carries both a VPLS and an EVPN. Written as asked, it would have accused a correct document
  twice on day one. The version that survives is its opposite: not «a line cannot carry two things», but
  «a link must say what carries it».
- **The recovery chapter now prints what does not add up, instead of printing the fields and going quiet.**
  A WAN line declared at the wrong site read, on paper, exactly like a right one — the card prints
  «provider · circuit id» and no site — and that is the worst place to leave something false, because the
  person opening that chapter is opening it on the night they have no time to verify it. A closing section
  carries the findings, each with its subject, and below them what **could not** be checked and why: a
  chapter that stays silent about what it did not examine reads like a chapter that found nothing. It is
  printed even when there is nothing to report, since a section that disappears reads as an oversight.
  The words come from the same dictionary the panel uses rather than a second copy: forty sentences
  transcribed diverge at the first one reworded, and on screen that divergence is visible while on paper
  it is not.
- **One definition of what counts as an inconsistency and what counts as a gap.** The classification lived
  in two places — the engine and the panel — and matched by habit, not by any gate. A check added to the
  engine alone would have been computed and **never drawn**: the panel renders only what appears in one of
  those two lists, so a row in neither exists and nobody sees it. That is the thirteenth time a definition
  split in two has surfaced in this codebase; the panel now imports the engine's lists, and a bench fails
  if any audit list is missing from both — or sits in both.

- **A floorplan gains a second level of containment: the storey.** A drawn plan had one — the room —
  and the buildings it documents have two. `storey` is a structural element with *exactly* the room's
  properties (same drag, resize, lock, colour, opacity), because it is the same shape at a larger
  scale and two definitions of one shape diverge at the first change. It stacks below the room, which
  stacks below the devices, and that ordering is explicit rather than left to DOM order: a container
  that covers what it contains is not an aesthetic detail, it makes the contents unselectable. Its
  label sits top-left instead of centred, where the rooms inside it would otherwise cover it. It also
  joins the server's layout denylist, or a storey would have walked into the asset inventory as if it
  were a device — the two lists are kept in step by a bench that already existed.
  ⚠️ The id is `storey` and not `floor` deliberately: in this catalogue `isFloor` already means «sits
  on the floorplan rather than in a rack», so a type called `floor` would have made `TYPES.floor.isFloor`
  a sentence nobody can read. It is also separate from the multi-floor design sketched earlier, where a
  floor is a *canvas* carrying its own plan; this is a rectangle on the sheet. Both can exist, and the
  word will have to be split when the other arrives.
- **The NetBox import stops flattening the location hierarchy into a name.** NetBox locations nest —
  Site → Location → sub-Location → Rack → Device — and the import said so in a comment while doing the
  opposite: it collapsed the parent chain into the room's name, «Floor 1 · Server room», *«instead of
  pretending a hierarchy the document cannot represent»*. The document can represent it now, so the
  parent location becomes the storey and the child becomes the room, carrying its own name — inside a
  box already labelled «Floor 1», a room called «Floor 1 · Server room» says the same thing twice.
  Four decisions come with it, each one a case the data actually contains. **Two levels are drawn, not
  N**: with Building → Floor → Room the storey is the *immediate* parent and whatever sits above stays
  in its name («Building A · Floor 1»), because faking three levels with two is the same lie one storey
  higher. **A storey is always top-level**, since a storey inside a storey would need a third level that
  does not exist. **A location holding devices of its own *and* sub-locations is a storey**, and those
  devices sit inside it next to the rooms rather than in an invented room NetBox never declared. And **a
  parent the read did not bring back** — out of scope, truncated — **is not a storey at all**, because that
  would be a rectangle with an id inside it. ⚠️ The decision line shown in the import panel promised
  «an InfraNet room does not contain another» and the bench against the real NetBox pinned the
  flattened names: both were true until this worked, and both are updated. The bench now proves
  something it could not before — that the room sits *inside* the storey — because a name reads
  correctly even when the geometry is wrong.

### Fixed

- **An edit made while the save was in flight disappeared, and the interface said «saved».** Press Save, move a device before the spinner is done, and the dot that means "unsaved" went out anyway — because the response handler cleared it unconditionally. The body of that request had been serialised *before* it left, so the edit was never in it: what the dot went out over was a save that could not have contained it. The window is around 200ms on a thousand-node project — which is exactly when somebody keeps working — and with autosave enabled it got worse rather than better, since the timer already armed found the flag clean and skipped, leaving the edit in memory until the next unrelated change. If it was the last action of the day it was gone. The document now counts how many times it has been dirtied: a save takes that number before serialising and hands it back on return, and the dot goes out only if nothing has arrived since. Whoever loads, creates or duplicates a project still clears it outright — there the document is clean by construction and there is nothing to compare against. ⚠️ The regression bench had to *open* the window on purpose by delaying the response: on a small project the request is a few milliseconds, and a race you win by luck is not a proof — tomorrow, on a faster machine, it would stop being won.

- **Two sessions saving the same project both got 200 OK, and one of the two afternoons vanished.** Nothing carried a version, so «somebody else wrote» was indistinguishable from «I wrote»: last one in won, silently, and the loser's client was told everything had gone fine. Two people documenting two different racks the same afternoon is not a laboratory scenario, and with `data/organization.json` — one per installation — it takes any two sessions, not two that opened the same project. A project now travels with an `ETag` derived from the file itself, and a save that presents a superseded one is refused with 409 instead of overwriting; the client shows what the other session wrote and when, and offers to overwrite rather than deciding. Whoever sends no `If-Match` keeps the old behaviour on purpose — the DCIM import, the scripts and the tests should not have to learn a protocol to stay alive, and a guard that breaks its callers is a guard that gets switched off. ⚠️ The version is **not** `updated_at`: `timestamp()` truncates to seconds, so two saves in the same second would carry the same marker — and two saves in the same second are precisely the case this exists to catch. A marker that repeats exactly when it is needed is not a marker. ⚠️ And the 409 carries an ETag of its own, which the client deliberately does *not* adopt: swallowing it would have let the next save through without asking anyone, disarming the guard on the first case it was built to stop.

- **«Sites and links» jumped back to the top of the list every time you changed anything.** Change a dropdown on the eighth site and you were looking at the first one again, with the row you were working on somewhere below. The panel redraws itself on every value change — that is deliberate, because a change can alter what other rows say — and rebuilding the container’s contents takes its scroll position with it. The position is now saved before the redraw and put back after, but only when the same tab is being redrawn: inheriting an offset from a list that is no longer on screen would be its own kind of wrong. An explicit request to move the view — the map sending you to a link’s row, or a freshly added row — runs afterwards and wins, which is the right precedence. ⚠️ The first version of this fix restored the scroll of `#org-body`, which is the element that looks like the scroller and is not: both it and `.org-pane` say `overflow:auto`, but the body is a flex column that hands the pane the remaining height, so the pane is the one that overflows. Measured at a 560px window: body 0px of scroll, pane 1346. Restoring the body was a no-op that reads exactly like a fix, and only measuring told them apart.

- **The floorplan grid ended, and you could walk off it.** Drag the plan a couple of hundred pixels past its origin and the squares simply stopped, with bare background beyond — which reads as the drawing having failed rather than as a boundary somebody chose. The grid was the repeating background of `#floor-canvas`, an element sized 5000×5000px, and a background can only be painted where an element is: it ended exactly where that rectangle did, and that rectangle’s top-left corner is the viewport’s — so the edge was two hundred pixels away in one direction and five thousand in the other. What made this worth fixing rather than enlarging is the asymmetry underneath: the *drawing* stopped at 5000, the *model* did not. Nothing clamps a device’s coordinates and nothing clamps the pan, so a device dragged past the edge stays there, is saved there, and sits on a piece of plan with no grid under it and no word said about it — measured with a probe at (6000, 6000), which paints perfectly well. The grid is now a child of the viewport rather than of the canvas, and what moves is its `background-position`: a repeating pattern has no edges, so there is no size left to run out of and no extra element to pay for — it is the same single div as before, and it shrinks from 5000×5000 to the size of the window. ⚠️ The invariant that makes a grid true rather than decorative is that **every line drawn is a position something snaps to**, and it now has to hold at every magnification, since the cell is the snap step times the zoom. Below about 40% the cell would collapse into a flat wash, so it **doubles** — never halves: doubling draws a subset of the snap positions, which stays true, while halving would draw lines where nothing snaps, which is a grid that lies about where you will land. Verified from 5% to 500%. One more thing fell out of it: the step is no longer written in two places — the renderer used to set the cell from `FLOOR_SNAP_STEP` while the transform set the position, and those two would have contradicted each other the first time either one changed.

- **«Save» has its word back at 1920, which is where most screens are.** It had been collapsed to its icon on a measurement that was right and applied in the wrong place: at full size the bar asks for 1938px, more than the commonest desktop width, so at 1920 one of the six words has to go. But that 1938 is measured *above* 1920, where the buttons still carry their full padding — and the rule that hid the word lives inside the very media block that takes that padding away (17 buttons × 4px) and hides the user label too. Inside it, the room was already there. Measured at 1920 with all six words lit: the search box sits at 428px against a 320 basis — 108px free — and «Save» costs 33.7 of them. It fits, with 74 to spare. It yields at ≤1800 now, immediately before «Multisite»: the ranking between those two is the one that was asked for and it has not changed, only the width at which it applies. ⚠️ Two things this uncovered. The block's own comment promised the labels come back above 1920, and they do not: above it the full padding returns and the bar wraps until about 1981 — measured at 1930, two rows — where the runtime fitter takes two of them away again. And «Save» is not a label like the others: on a successful save the button writes «Saved» for 1.8 seconds, so with the word hidden that confirmation was unreadable on the commonest screen there is, leaving only the icon's tick. The fitter's ladder was re-ordered to match, because two ladders disagreeing means the result depends on whether the window shrank or a badge lit up last. Every word now has its own step, six instead of five: «Save» and «Export» used to share the first one, and sharing it would have cost «Save» its word as soon as two status badges were lit together — which on a project with SNMP is the normal state, not the rare one. Measured at 1920: one badge is absorbed by the search box and no word yields; at two, «Export» and «Dashboard» go and «Save» stays; it takes three before «Save» yields. The guard is end-to-end and asserts the rendered width of the labels, not the CSS: that «Save» reads at 1920, and that one step at a time the ladder gives up Export → Dashboard → Save → Multisite → Discover.

- **A storey could be drawn but not moved and not deleted.** It appeared on the plan, it resized, and then it refused the two things you would try next — which reads as the feature being broken rather than one selector being out of date. The cause was a list: the layer that turns a click into a selection recognised a drawn container by naming its classes one by one (`.floor-node, .floor-room`), a list written when the room was the only container there was. The storey arrived and the list did not follow, so a click on a storey matched nothing, nothing got selected — and deleting works on the selection, so the Delete key had nothing to act on. Resizing kept working because the handle walks up to its parent instead of asking that selector, which is why the failure looked arbitrary. Nothing errored: a selector that finds nothing does not complain. The fix is to remove the list rather than extend it — the renderer marks every drawn container with one shared class and every consumer looks for that, so the next container type works on the day it is born instead of waiting for somebody to remember six files. This is the second time this exact list has cost something: the first was the dragging of rooms, and the warning left in the code after that one described this bug before it happened. The appearance moved onto the shared class too, in the order base-then-differences, which incidentally revived the storey label's own padding — the old shared rule came *after* the specific one and had been silently overwriting it.
- **The properties panel called a storey a room.** Its name field was labelled «Room name» whatever you had selected. The label is now just «Name»; the panel's subtitle already says which kind of thing it is, so the type does not need saying twice — and it stops being a per-type string that has to be added every time a container type is.

- **Running the headless test suite could have overwritten your organisation.** The end-to-end harness spawns a real server with every store redirected into a throw-away directory — projects, skins, users, API tokens, the assistant and DCIM configs — and the organisation was the one left out. It is *one per installation* and lives in `data/organization.json`, outside any project, so redirecting the projects directory never moved it: a test that opened «Sites and links» and pressed Save would have rewritten the real sites, WAN lines and links of whoever ran the suite — and a test suite has to be safe to run on a working copy. Nothing had done it yet, for exactly the reason that made it possible: no headless test had ever reached that panel. It has two now, and they cover the chain rather than the screen — the WAN lines arrive from a mock NetBox and add themselves to what was written by hand, the panel offers the lines of the link's *two sites* instead of every line in the organisation, and a ticked line is saved and read back off the route, which is the step that used to drop it in silence. The other half is the opposite rule: what is already declared keeps being shown even when it belongs to a third site, and even when the line has been deleted since — a value that lives in the model and cannot be seen on screen is impossible to switch off, and it goes on printing on the recovery card.

- **The import knew which port the WAN line lands on, and threw the answer away.** «Which box do I put my hands on» is the first question of a line outage, and the dossier answered it with a dash on all seven lines of a real archive — while the application, one step upstream, had the answer. `lib/dcim-wan.js` resolves the port by following the cable from the circuit termination to an interface, and the four-site bench *asserts* it resolves for **every** uplink against a real NetBox; then the result lived and died inside that module — nothing outside it read `wanPort`, and the panel wrote `wanIfRef: null` on every imported line, swept in beside two fields that are empty for stated reasons (NetBox holds no SLA; a public address is not the address of a WAN interface). The port had no reason of its own; it had simply never been joined up. The line now carries its port as far as the printed card — `MI-FW-01/port1` — composed in the module that owns the shape rather than by whoever consumes it, with the slash that is already this repo's way of writing device-plus-port. `declared` and not `measured`: NetBox is an archive of declarations, and following a cable is *reading* one, not measuring the network. ⚠️ A partial reference stays partial — an interface with no device, or a device whose interface NetBox does not give, is written alone rather than stitched to a half that does not exist. ⚠️ And the field is now **in the panel**, which it never was: `_setField` had handled `wanIfRef` since the beginning and no template ever rendered an input for it, so the branch was unreachable and the value could only ever have come from a machine — which is the one thing manual-first does not allow. ⚠️ The bench that certified this is green got a second assertion, because a test that stops one step short of the consumer certifies something the reader never receives; its verbose line was also printing `undefined`, reading a `name` field the resolver does not return.

- **A contractual bandwidth that no line can have reached the recovery card.** `0`, `-100` and anything else that is not a measurement went into the model untouched and printed on the WAN card as if it were a fact — in the one document somebody reads at three in the morning, where «Contractual bandwidth: 0 Mbps» is not an empty field but a statement that the line carries nothing. It was reachable by typing, not only through the API: the input is `type="number" min="0"`, and `min` does **not** stop a typed value — the browser flags `rangeUnderflow` and leaves the value perfectly readable, and the handler read `.value` without ever asking `validity`. The browser knew and nobody asked it. The rule was already written elsewhere and had been from the start: `lib/dcim-wan.js` refuses `n <= 0`, so an import could never produce this — it was the by-hand path that disagreed with the import path about what a bandwidth is. Both now say the same thing, from one definition. ⚠️ **No upper bound, deliberately**: 400G exists and 800G is coming, and a ceiling picked today would reject a real line tomorrow. An enormous bandwidth is implausible, not impossible, which makes it the audit's business — it reports without destroying — and not the normalizer's, which discards. ⚠️ And the panel now **says so** where you type it, instead of dropping the value on save: replacing a wrong number with a silent disappearance would have been the same defect wearing better clothes. This overturns a previously asserted behaviour (an explicit `0` used to be kept, on the reasoning that a written zero is a declaration); the test that asserted it now carries the reasoning for the change rather than a flipped expectation.

- **Two sites sharing one id both went in, and one of them vanished from the map.** Everything downstream indexes by id — the map keeps one box per site, `siteById` answers with the first it finds, the dossier chapter looks the device up in that site's project — so a repeated id is not a duplicate row, it is an identity that does not identify. The model kept all of them, the report counted all of them, and the map drew **one**: the second disappeared from the screen while remaining in the totals, and `dropped` reported `0`, so whoever saved was told nothing. It is the same shape as the missing `case` in the kinds `switch` fixed a day earlier — a record that exists and cannot be seen — and the same shape is now closed for uplinks and links too. The first occurrence wins, because it is the one read at the top of the file and because it is the only choice that does not depend on the order the caller happened to use; the second is dropped **here**, which is what makes `writeOrganization` count it (choice ④ of the store) and the panel say it. ⚠️ Deduplication is by id and **not** by the pair of sites: two links between the same two sites are the ordinary case — an MPLS primary and an IPsec backup — and a merge on the pair would have swallowed one of them.

- **The notes of the import result had no singular.** «Non proposte **1 linee** che non sono attive», «Non proposti **1 servizi**» — and four more like them. The two count sentences at the top of that same box have had both forms since they were written, for a stated reason: «Aggiunto 1 collegamenti» makes the reader doubt everything else on screen. The notes missed out because they take a different road — one key, looked up flat, with no plural variant — and nobody had given them one. Six codes carry a count and all six now have their singular in both languages, and the agreement runs through the whole sentence rather than just the number: «non **è** attiva … **importarla la** renderebbe **indistinguibile**». A seventh carries a count and is deliberately left without one: the multipoint note only fires above two sites, so «1 site» cannot happen, and a phrase for it would be a translation maintained forever and never seen. ⚠️ Both keys are named in full at the call site rather than composed as `key + 'One'`: the i18n ratchet reads keys from the source, so a composed one would be invisible to it — free to be missing from the dictionary, or to sit there unused, without any test going red.

- **A note in the import result printed a raw `{n}` at the reader.** The placeholders in those notes were substituted with `String.replace` and a plain string, which changes only the FIRST occurrence — so the one sentence that names the same placeholder twice («touches 3 sites … not {n} pairs») showed the second one verbatim. It surfaced the moment an archive with a multipoint L2VPN over three sites was read; nothing before had one. The substitution is now global, and it goes through `split`/`join` rather than `replace` for a second reason paid in the same hour: in a replacement string `replace` interprets the dollar sequences, and these values are site and service NAMES written by whoever documents — a name containing a dollar would have been rewritten instead of printed. The sentence itself was wrong too and is fixed rather than patched: the second number was the count of *pairs*, which is not the count of sites (three sites make three pairs by coincidence; four would make six), so it no longer promises a number it was not computing.

- **The dot between the two sites and the kind of link was rendered as a doubled character.** In `styles/07-modals.css` the separator lived in a `content:'·'` whose bytes had been double-encoded — UTF-8 text read as latin-1 and written back out — so every row of the links panel read the site pair, then a doubled separator, then the kind. Nothing could catch it: the code runs, eslint is silent, the tests pass; only the eye sees it, and only on that panel. Two more of the same were sitting in comments in the same file. The byte guard that already refuses NUL bytes and lone CRs now refuses double encoding too, ⚠️ and it comes with its own probe: the first version of the detector was green on the whole repo *and* on the very defect it was written for, because it looked for a continuation byte where the sequence actually carries a `C2`. A guard that is never tested against the real case is a guard that always says yes. `data/` is out of its scope on purpose — the OUI and PEN registries carry the mangling in the source data, and straightening it would mean guessing at a company's name.
- **Deleting one of two identical networks deleted both.** Reported from the screen: two rows reading `10.10.20.0/24`, and the × on one took away the other. They were not two rows in any sense the model understands — here a network **is** its CIDR, so `findPrefix` only ever found the first, `upsertPrefix` only ever wrote to the first, and `removePrefix` filters by key and therefore removed *every* copy. The second row was a ghost that only the drawing could tell apart, sharing one tooltip, one occupancy figure and one expand state with the first. The DCIM import wrote them: in NetBox the same prefix legitimately exists twice — in two VRFs, or once tied to a VLAN and once not — and those are different networks *there*. The import now merges them into one row and **says so** (`prefix.collapsed`, exactly like the VLAN collapse right beside it), keeping the VLAN and filling empty fields from whichever declaration had them; and the load-time migration repairs documents already saved that way, one-way and idempotent, so nobody has to re-import to be rid of the ghost. ⚠️ The first version of the merge kept the other row's description only when that row arrived *first* — and on the real archive it arrives second, so the description vanished. An order-dependent merge is one that passes its test and loses data: it is now order-independent, and the test runs both directions.
- **On a hub-and-spoke map the sites sat on top of each other and the links disappeared under them.** The ring radius made sure two *neighbours on the ring* did not touch — and nobody was comparing them with the box in the MIDDLE. It never showed while a site was a dot; it appeared the day a site became a box holding its WAN lines, its networks and its counts, and it got worse as the boxes filled up. Measured with the real sizes the browser reports (300×140): the hub and its spokes overlapped by 122px, and the link between them ran *backwards*, entirely underneath, with a sliver of its label peeking out between two boxes. The radius now also clears the centre, and the separation uses the axis test — two axis-aligned boxes are apart when ONE axis separates them — rather than the sum of the two boxes' radii along the line, which is the formula that comes to mind first and leaves a wide-flat box overlapping a tall-narrow one at 45°. And the link's kind is now a **badge** on the line rather than words floating over it — which is only readable if the space between two sites is actually reserved for it, so the renderer (which already measures the boxes to redraw them at their real width) measures each label too, gives every link a pill of its own size, and asks the geometry for a gap wide enough. The gap is **two numbers, not one**: a badge is wide and short, and reserving its width in height as well would make a map with one branch above its hub three times taller than it needs to be. How wide that space must be is a question only whoever knows the font can answer; the pure module just receives the two numbers, and never shrinks below its own minimum. Nothing changes for a ring layout — the defect was the centre — but the badge's space is honoured there too, because two neighbours on a ring can be linked like any other pair. The guard that should have caught the overlap only ever compared ring neighbours; it now compares every pair.
- **Every port MAC was being lost when importing from NetBox 4.2 or newer.** NetBox 4.2 moved MAC addresses into objects of their own: the flat `mac_address` field is still on the interface but it reads `null`, and the value lives in `primary_mac_address`. The mapper already knew this and handled both shapes — but only for the virtual NICs of VMs; physical ports read the flat field and nothing else. Measured against a real NetBox **4.6.7**: every imported port came back without a MAC. That is not a cosmetic loss — `port.mac` is what `macKey`, the presence audit, FDB matching and hardware-identity drift are all built on, so an import silently produced a document that could not be reconciled with the network it described. The rule was already written, in one place; the other place never got it, which is this codebase's most familiar failure. Both shapes now work everywhere, and an interface carrying neither still gets no MAC invented for it.
- **A trunk's native VLAN now survives the import from NetBox.** In NetBox `untagged_vlan` means two different things depending on the interface mode, and both are a VLAN somebody *declared*: on an access port it is the PVID, on a tagged port it is the **native**. The mapper only read the first case, so on every trunk imported from a DCIM the declared native was read and thrown away. That is not cosmetic: InfraNet has the field for it — on a trunk `vlanOvr` **is** the native, which `lib/link-vlan-color.js` states in as many words — and builds an **error**-level diagnosis on top of it. `native-mismatch` (`lib/cable-validate.js`) catches two switches whose trunk ends declare different natives, which is untagged traffic crossing where it must not; on any project born from a NetBox import that check could never fire, because both ends arrived empty. A tagged interface with no `untagged_vlan` still gets none — an absent field at the source stays absent here. Found by a new two-site import smoke (`_local/netbox/`), not by a report.

- **Which project opens at start-up is no longer a coin toss.** `updated_at` is written truncated to the second, and the project list sorted on nothing else — so two projects saved within the same second compared *equal*, and what actually decided the order was `readdirSync`: lexicographic on file names, which puts `10.json` before `2.json`, and is not guaranteed by the filesystem in the first place. Since the app opens `list[0]` on boot, the same data could open a different project between two restarts, and the picker could list the same projects in two different orders. Ties now break on the id, newest first — ids grow over time, so at equal seconds the last created is the last touched, which is the direction the sort already had. Found as an intermittently failing e2e — the boot landed on a project with no devices — and it had been failing on the unmodified branch too: the timing was what varied, never the code.
- **Three fields the NetBox import writes had no class, so nobody had decided what an export does with them.** `link.color` and `link.lengthM` (the cable's colour and length, read from NetBox but also typed by hand in the cable panel) are **documents** — the rule for dual-origin fields is that `document` wins, because getting it wrong that way leaves one extra field in an export the user made, while getting it wrong the other way deletes their work. `port.overflow` is **derived**: it is a comparison the importer computes (`slot > layout.dataPorts`), nobody writes it, and it is recomputed on the next import — so it now stops travelling in a portable export, where an unclassified field was silently kept. The guard that catches this went red the moment a project imported from NetBox sat on disk, which is exactly its job; the field census predates the DCIM import, so the three are listed as known-absent-from-the-sample rather than pretended into it.
- **The path in the sub-header no longer says «No project» while a project is open.** It reads the name out of the header's `<select>`, and that `<select>` gets *rebuilt* on every project list refresh — which happens **after** the project is loaded and redrawn. On a cold start the bar therefore drew from a list that was still empty and wrote «No project» under a fully loaded project, until the first click redrew it and quietly fixed it. The list refresh now redraws the bar it feeds, and the bar keeps the last known name instead of asserting «none» whenever a project is in fact open: not knowing the name is not the same as there being no project.

- **A toolbar button's height no longer depends on whether its label happens to be visible.** With
  `line-height: normal` the height came from the content: a button showing a word was 32px and the same
  button was 26.4px once its label collapsed to sr-only at a breakpoint — so the bar carried three
  different heights at once (26.4 · 29 · 32) and they changed as the window resized. An explicit
  `line-height` fixes it, in `em` rather than as a bare number: a number is inherited and recomputed
  against each child's own font size, which made the Dashboard button's larger icon grow it by 2px.
  The icon needs the same line box as the word, and Font Awesome sets `line-height: 1` on its own
  classes, so it inherits explicitly — without that, a button whose label was hidden went straight back
  to the glyph's height. All seventeen buttons are now one height, and the header does not get taller:
  «Verify» never loses its word, so the row was already that tall.
- **The multi-site button says its name.** It was an icon with a tooltip; it now reads «Multisito» and
  takes its place in the header's yield ladder. ⚠️ That ladder had to be re-ordered rather than extended,
  and the measurement is why: at full size the bar already asks for 1938px — more than the commonest
  desktop width — so a sixth word does not fit at 1920 and one of the six has to go. «Save» yields first
  now, moving from second-to-last to first: between a word for an action that already has its own key,
  its own state and autosave, and the name of *where you are going*, the one worth reading is the second.
  The runtime fitter was re-ordered to match, because two ladders disagreeing means the result depends on
  whether the window shrank or a badge lit up last. And «Save»'s old rule at ≤1280 is gone rather than
  left behind: a rule that can no longer fire reads exactly like one that can.

### Removed

- **The «next step» nudge is gone from the sub-header.** It sat in the middle of the bar on every screen, permanently, telling you what to do next — and a suggestion that is always on stops being a suggestion and becomes furniture: it was still lit on a fully documented project, competing for the eye with the numbers beside it, which are facts. The engine behind it is **not** removed: `lib/onboarding.js` (`nextStep`) and its tests stay, because the assistant (`src/app-ai.js`) still offers the same step — in the place where advice is asked for rather than imposed. What went with it is only its rendering in the bar and the four label keys nobody else used; the deterministic step itself keeps one home instead of two. The centre of the bar now holds just the active VLAN filter, which appears when there is one and collapses when there is not.

### Changed

- **The «add» buttons moved to the tab bar, one per tab.** They used to sit at the end of each list, so adding the twelfth site meant scrolling past eleven to reach the button — and after the redraw the button had moved further down than it was before. Now the active tab shows its own button at the right of the tab bar, in one fixed place: «Add a site» on Sites, «Add a WAN line» on WAN lines, «Add a link» on Links, and nothing on Map or Coherence, which are a view and a report rather than lists you add to. The map’s empty state keeps its own invitation, because there it is the only thing to do and an invitation is a different object from a toolbar. ⚠️ A new row is created at the *end* of its list, which is now off-screen — so an add would have looked like nothing happening. The panel scrolls the new row into view and marks it, the same way the map already brought a link’s row under your eyes, and by the same means: the ids are compared as dataset values rather than pasted into a selector string. The three empty lists gained a note of their own, since the button that used to be the only thing on an empty tab is no longer there — and the notes deliberately do not say «use the button at the top right», because a sentence that points at a place on the screen is false the day somebody moves it, and nothing checks sentences.

- **The Save button sits next to the project bar now, instead of three groups further along.** It used to come after Multi-site and Export, which put the thing you press to keep your work behind two things you press to go and look at something. It saves the project the selector right beside it has open, so the two now read as one gesture. The order of these buttons is also the tab order, so Save comes before Multi-site and Export there too — the same priority, for anyone who never touches the mouse. Nothing else moved, and no CSS rule depended on the position: there are no adjacent-sibling selectors on those ids, which was checked rather than assumed.

- **«I could not check» stopped meaning «there was nothing to check».** On an organisation of four independent sites — none of them declaring itself a spoke — the coherence tab listed «spoke sites with no link to a hub» among the checks that could not run, with the reason «no site is declared a hub». Both halves were true and the row was still wrong: the question «does every spoke reach a hub» does not exist until somebody declares a spoke, and asking the reader to remedy a question nobody asked is how the one list that has to stay credible fills up with reproaches — after which nobody reads it, and the genuine blind spots go with it. The check now looks for spokes first: with none, it reports nothing and says nothing. With spokes and no hub it still declares itself blind, because there the question is real and unanswerable. ⚠️ The order matters and is pinned by a test: the other way round it would tell somebody with no spokes that they are missing a hub — accusing a complete document of being incomplete.

- **And a link chip on the map says who sells it.** Three links run between Milan and Rome, and «VXLAN» does not tell you which contract to pull up when one of them is down. The chip now reads operator, then nature, then how many networks it carries — in the same order the site boxes have always printed their lines («TIM · MPLS»), because two places stating the same thing in two orders read as two different things. The operator is present on three links out of eight on a real archive — it is missing on everything nobody sells you — so the label is composed by filtering, and an absent operator leaves no separator hanging off nothing. The paper map composes it the same way, from the same order: it is the same map, and two compositions would drift apart on the first edit to one of them.

- **The inter-site map zooms and pans, with the floor plan's own controls.** Four sites fit on a screen; eight, each with two lines and three links, do not — and until now the only recourse was to squint. The map now takes a wheel to zoom and a drag on its background to pan, with the same minus/percentage/plus widget that sits on the floor plan, because someone who has learned to move around one building should not have to learn it again one floor up. It is the same `{x, y, zoom}` model as `floorView`, deliberately: that model had already solved the part that is easy to get wrong — zooming toward the **cursor** rather than the centre of the frame, so the box you are looking at stays under your finger.
  The drawing stays **vector** at every magnification: the transform rides on a group inside the SVG rather than scaling a bitmap, so a link label at 600% is as sharp as at 100%. Three decisions are worth writing down. The frame's «fit everything in» view is computed once from the group's own bounding box and left alone — asking the SVG for it instead would have made the fit follow the zoom and chase itself smaller on every wheel click. A drag starts only from the **background**: on a site box or a link chip a click already means something, and a pan starting there would make them hard to press. And the percentage is a button that returns to fit, so there is always one gesture back to the whole picture — with the view kept in the panel's own state, not in the document, since how you are looking at something is not something you documented; it survives a redraw and never marks the organisation as unsaved.

- **A link between two sites answers two questions, and the model was only letting it answer one.** «MPLS» and «IPsec» sat in the same dropdown, and they are not alternatives: an IPsec tunnel runs *over* the public Internet, or *over* the company MPLS, and with a single field declaring one of them erased the other. On a real archive a site-to-site tunnel arrived as `ipsec` and the circuit carrying it simply vanished. There are now two closed vocabularies — **transport** (Internet · MPLS · VPLS · VPWS · VXLAN · EVPN · direct link · other) and **tunnel** (none · IPsec · GRE · WireGuard · OpenVPN · L2TP · SD-WAN · other) — and «IPsec over MPLS» is a sentence the document can finally hold. It is not a division invented here: NetBox keeps L2 services in `l2vpn.type` and tunnels in `tunnel.encapsulation`, two separate models with two closed vocabularies. The import was already reading them from two places and then flattening them into one; it has stopped flattening them.
  Three judgements are written into the vocabularies. **SD-WAN is a tunnel, not a transport**: an SD-WAN is an overlay — precisely the thing that runs over one or more transports — which is why the field recording which WAN lines carry a link exists at all. **`none` is not `null`**: «I looked, there is no tunnel» is a decision an MPLS in the clear deserves to record, and «I have not written it» is a different statement — the same distinction the link state has always made. And **GRE and L2TP live on the tunnel axis although they encrypt nothing**, because the axis asks what runs *on top*, and a GRE runs there exactly as an IPsec does; calling the axis «encryption» would have forced the model to lie about two of its six values.
  ⚠️ **Migration invents nothing.** A stored `kind` moves onto the axis it belonged to and the other axis stays *unstated*: `ipsec` becomes a tunnel with no declared transport, because the old field never said what it ran over — writing «Internet» there would be inventing precisely the fact this change exists to make writable. It runs once, only when neither axis is set, so re-reading a migrated document leaves it alone.
  ⚠️ **And a nature outside the vocabulary no longer drops the whole link.** Rejection had a reason while `kind` discriminated a union — an unknown nature left an object with no shape. With two optional axes it does not, and throwing away a link entire — both ends, the reachable networks, the ticked lines — over one misspelled word is a worse cure than the disease. The word does not enter, the row stays, and the screen and the paper both say «nature not stated». Two consequences worth naming: a circuit type slugged `internet` is now *recognised* rather than filed under other, and one slugged `sd-wan` no longer is — a circuit is a transport, and an operator's product name for it is not the tunnel.

- **The WAN line card stopped being an inventory and became a recovery checklist.** The chapter exists for one night — the one the line is down — and it only answered the first half of it: who sells it, what it is called on the contract, what was bought. Nothing on the card said how to bring it back up. Five fields now do. **How the interface is addressed** (static / DHCP / PPPoE): the first question in front of a router to reconfigure, and it decides which of the others mean anything. The **next hop**: with an address and no gateway a static line cannot be rebuilt from the document at all, which was the largest hole this card had. The **delivery VLAN**: the tag the operator hands the service over with, and the classic «the port is up, the cable is right, and nothing passes». The **MTU**: 1492 on PPPoE, lower under a tunnel — the «everything works except large packets» fault, which without this number gets hunted for hours. And **who to call**, run through the same credential-stripping guard as the backup pointer, because a portal URL with a password inside it is a secret and this page gets printed and passed around. None of the five is filled by any import: NetBox has no next hop and no delivery tag, and deriving them from a WAN interface would be a correspondence rather than an identity — so they are declared by hand, like the networks a link makes reachable.
  ⚠️ **The netmask is deliberately not among them.** The routed block already lives in the public-addresses list, which is a list precisely so it can carry the interface address *and* the block somebody sold you; a `netmask` field would be a second definition of the same fact, which is the bug family that has come back twelve times in this codebase. Nor is the QinQ outer tag: no archive we have looked at carries one, and a field that is almost always empty teaches people to read the whole card as noise — when a real archive shows one it will get its own field, which is the method that has already worked four times here.
  ⚠️ And they earn their place rather than adding five more dashes. The audit gained **a line that declares itself static and does not say who it talks to** — counted as a *gap*, not an incoherence, because nothing contradicts anything, a row is missing — and the dossier's chapter header counts those lines beside the ones with no circuit id. On DHCP and PPPoE the gateway row is not printed at all: a dash there would claim a datum is missing that does not exist, and a dash that accuses a correct document teaches people to stop reading dashes.

- **An IPsec link now carries the two proposals you actually retype, and a pointer to where the key lives.** A tunnel does not come back up from a phase-1 *name* and an IKE version: it comes back up from the two sets of parameters both ends must have identical — cipher, integrity, Diffie-Hellman group and lifetime for phase 1; cipher, integrity, PFS and lifetime for phase 2. Get one of them wrong and you have a tunnel that will not establish and a log that does not say which one, which is the classic lost hour of this job.
  ⚠️ **Two strings, not twelve fields.** Every platform writes a proposal its own way — `aes256-sha256-modp2048`, `AES256/SHA256/DH14/28800`, a profile name — and splitting it into structured fields would mean normalising across vendors, i.e. deciding what «DH14» means on a box that does not write it that way. Here you copy what the console shows and you retype it identically, which is the only operation that matters. PFS deliberately has no field of its own: it lives inside the phase-2 proposal, where every device writes it, and a separate field would be the same thing said twice by two rows that diverge on the first edit.
  🔒 And the pre-shared key is **not** stored — only *where it lives*: a password manager entry, a vault path. It runs through the same guard as the backup pointer — imported, not rewritten, because a second definition of «this is a secret» diverges the first time one of the two regexes is touched. The panel says so while you type rather than letting the field empty itself on save: a value that disappears without a word is indistinguishable from one that was never typed. This page gets printed and handed to somebody; InfraNet is a register, not a vault.

- **Two fields left the multi-site model, and one that was on the list stayed.** `slaRef` was free text and **zero out of seven** on a real archive: a "reference" nobody ever writes is not a datum, it is a box. What replaces it is a contact you can actually dial; a numeric restore time was drafted alongside it and then dropped, because deciding whether to wait or fail over is not a thing the card is consulted for at 3am — the phone number is. `topology` on a single link is gone for a different reason: hub-and-spoke or mesh is a property of the *set* of links that make up one service, and a single link between two sites is point-to-point — calling it hub-and-spoke is a sentence about the design, not about that link. It sat on 2 links out of 8, both written by the import, which read NetBox's per-**termination** role (hub / spoke / peer) and flattened it onto the link, which is already an interpretation rather than a reading. Downstream its only audit check compared that word against the **sites'** declared roles — that is, it existed to catch the divergence the copy itself created. Removing the copy removes the class of defect and the check that chased it. The shape of the organisation is stated by the site roles, which is one definition in one place; and when multipoint **services** are modelled — they are refused today — the topology belongs there, where the set lives. ⚠️ `name` was on the same list and is staying: it is filled on **5 links out of 8**, and it is not competing with the circuit id for the identity. Three different things that merely look alike — `circuitId` is the operator's number on the contract, `phase1Name` is an object in a device's configuration, `name` is what the link is called in a meeting — and deleting the human handle because two neighbours are also identifiers would have been the opposite mistake.

- **The overview declared it was not looking at the WAN, and that had stopped being true.** The perimeter strip at the foot of every lens — «what I am not looking at» — exists so that the absence of an alarm is never read as a clean bill of health, and the rule written beside it is that a dimension leaves the list once it is modelled: `power`, `health` and `lifecycle` left it that way. `wan` did not. So after the multi-site layer landed, the chip was telling the reader that the lines to the ISP, their contracted rate and the links between sites are «not modelled» — while a panel, an audit, a map and a dossier chapter model exactly those. Removing it would have been the opposite falsehood: this engine reads **one project**, and the organisation is one per **installation**, so from inside a project those lines genuinely are not in view, and a silent removal would have promised a verdict nobody computes. The third tier the list had defined for precisely this case — documented or measured elsewhere, but not part of a verdict here — had never been used by anything: `wan` now carries it, its chip is marked, and the hint names the panel where the lines are documented and what is still judged nowhere, which is failover and whether an SLA is being met.

- **The multi-site panel had two words for one thing, and one of them already meant something else.** What a site buys from a carrier was an *uplink* in the panel and a *WAN line* in the dossier — and «uplink» is the word this application already uses everywhere else for a port facing the layer above: an access switch's uplink to distribution, an access point's wired uplink, the SFP block on a switch front panel, the WAN ports counted on an SD-WAN appliance. It was not a subtle clash: one sentence in the DCIM import used both words for the same object in a single line, and so did the note explaining why an inactive circuit is not imported. The carrier circuit is now a **WAN line** throughout the panel — the tab, the buttons, the audit, the messages — which is what the dossier already called it and what you call it on the phone to the carrier; «uplink» goes back to meaning a port, which is what it means in the rest of the product. Nothing in the model moved: the field is still `uplinks[]` and `underlayUplinkIds`, because code names are not user words and renaming them would be risk with no reader on the other end. ⚠️ The sweep was left half done, and a re-read caught it rather than a test: the DCIM note that this very entry had *named* as the clearest case of the clash — «the line is read in the Sites and links panel, where uplinks live» — was still saying it in both languages, because the pass had walked the `org.*` keys and the clash also lives wherever that panel is referred to from elsewhere. No gate can see this: the keys are unchanged and the two languages are allowed to differ. After a rename the only real check is to search the old word again and account for **every** remaining hit one at a time — which is also what confirms the ones that must stay, since on an SD-WAN appliance the WAN uplinks it counts are still ports of that box and keep the word.

- **The coherence report named things in words that did not survive being read.** It said a link *carries* a network; a link does not carry a network, it makes it **reachable** — and the field has been called `reach` all along, with the form label already reading «Networks reachable at …». It said «networks that are at no site», which is not a sentence anybody parses under pressure. And one title was not merely unclear but *wrong*: «Spoke sites with no declared hub» named the reason a check **cannot run** rather than the defect it had actually found, which is a spoke with no link to a hub that does exist — the two are opposite states, and the first one already has its own line in the «could not be checked» register. The two ends of a link are now called **sites**, because in that same panel «end» was already the *device* holding the tunnel, so the reader had to guess which of the two was being accused. In English «Incoherences» is now «Inconsistencies», the word English actually has for two statements that cannot both be true, and a duplicated prefix at two sites now says «overlapping addressing» out loud, because that is the name of the fault. The link state options were «Su» and «Giù» in Italian, which nobody says about a tunnel: they are «Up» and «Down», and the dossier's legend follows, since it prints the same two words from the same definition.

- **Which WAN lines a link runs on is no longer a question you can only ask about SD-WAN.** The field existed — `underlayUplinkIds` — and lived on the `sdwan` kind alone, where the word *underlay* had made it look like an SD-WAN concept. It is not one: an IPsec tunnel leaves on a line, an MPLS or a VPLS is *delivered* over an access circuit, and «the Milan line is down — what falls with it?» is the same question whatever the kind. It is also the question the dossier's recovery chapter exists to answer, and until now that chapter kept the two halves apart with no relation between them — the lines on one card, the links on another. Declared on any kind, the relation now survives the save (on an IPsec the server used to normalise it away in silence, without even counting it among what it dropped) and prints on the recovery card of every link. Three things it deliberately does not do. It does not derive itself: matching a tunnel's peer address against a declared public address is a *correspondence*, not an identity — a NAT in front of the router breaks it, the peer address is the address of the far end, and on the real archive not one of them matches — so it is declared by hand, like everything else no device can report. It stays one flat list rather than one per end, because every uplink already carries its own site: two lists would say the same thing twice and contradict each other the first time one was edited. And an empty list still means «not declared» rather than «runs on nothing» — on a dark fibre between two buildings empty is the right answer, because that link *is* the line. ⚠️ The panel now offers the lines **of the two ends** instead of every line in the organisation: a Turin line cannot carry a Milan-to-Rome link, and offering it invites a mistake nobody re-reads. What was already declared stays visible even when it falls outside those two, and even when the line has been deleted since — a value that lives in the model and cannot be seen on screen is impossible to switch off, and meanwhile it keeps printing on paper.

- **The box that reports a NetBox WAN read was 389 pixels of prose; it is now three lines and two drawers.** It was saying four different things in one typographic register: an outcome, a census of the circuit types it met, a footnote about that census, and seven refusals each carrying its full reasoning. Same size, same colour, same bullets — so the fact that actually matters, *nothing changed, you are up to date*, had to be reconstructed by reading two sentences and adding `0 + 2`. Three things changed and none of them is a deletion. The outcome no longer opens with a zero: «Added 0 WAN lines» leads with the least interesting number in the sentence, and there is now a phrase for the nothing-added case that says how it went first and keeps the count that matters — how many were already there — as its follow-up. The notes are **grouped by their code**, which is to say by their reason, because that is the structure the data already had: a repeated code prints its class once with a count instead of once per row, and a NetBox holding four VXLAN tunnels no longer prints the same VNI paragraph four times. And both the notes and the type census start **closed**, with their count on the face of the summary — «7 notes on this read» — so nothing is hidden, it is ranked: the reasoning is word-for-word what it was, it just waits to be asked for instead of being served at every import to somebody who has read it twenty times. ⚠️ The count says «notes» and not «not imported»: a third of those codes are caveats about the read itself (truncated, filter refused), and calling them all discards would say something false about them. ⚠️ Every note code must now carry a class name in both languages as well as its sentence — the same ratchet that already refuses a code without a phrase now refuses one without a title, so the next reason to be added cannot arrive as an untitled group. The old census heading became the summary and its key was left with nobody asking for it; the ratchet caught that too, and it is gone rather than kept translated forever.

- **A link on the map opens the link: click its badge and you land on the row that describes it.** Clicking a site already walked down into that site’s project; the links did not answer to anything, and the question you ask a map — «what is this line here?» — cost three moves: change tab, scroll, then recognise the row among the others by the two site names. Which is the question you started from. The badge is what is clickable, not the arc: the line is two pixels thick and catching it with a mouse is a shot, and an arc live along its whole length steals the click meant for the site it passes. Landing is not just a tab switch — the row is brought into view and marked for a moment, because after the jump twelve rows look alike and finding it again is the work the click was supposed to remove. The mark is an animation that ends by itself, and it stays put instead for whoever asked for less motion: it is information, not decoration. And since the badge announces itself as a button, Enter and Space now press it — as they now do on the site boxes, which had been claiming to be buttons since the map was drawn.

- **Both ends of a link are named by their site, not by their position.** «Peer IP (first end)» and «Peer IP (second end)» made you scroll back up to two dropdowns six fields above to find out which end was which — while filling in the one pair of fields where swapping them leaves no trace. They now read «Peer IP, as seen from Verona», the shape the device and reachable-networks labels already used, and a single helper composes all six so they cannot drift apart. **«As seen from», not «at»:** in this model `endpointA.peerIp` is the address of the *other* end — the one typed into the tunnel configuration on this one — so «Peer IP at Verona» would have stated the exact opposite, and two plausible addresses in the two wrong fields is a mistake nothing downstream can catch. When a link points at a site that no longer exists the label now falls back to the missing site’s id instead of trailing off into nothing: the broken reference is already reported by the coherence pane, but a label ending in a blank does not even look like a gap.

- **The free-text name of an `other` link sits next to the kind it names.** It was six fields below the dropdown, among the per-kind properties, and the two new fields above pushed it further down — far enough that it was reported as «isn't this the same as State?». It is not, and never was; but the two labels used the same noun for two different roles, and nothing on screen tied them together. `vrf`, `overlay` and `media` are *properties of the link*; that label *completes the kind itself* — it is the dropdown's own question answered in words — so it now follows the dropdown, as its «Description». Nothing changed in the model, and a link of any other kind still does not show the field at all.
- **The panel’s lists are comma-separated, like the rest of the app.** Site networks, public addresses and the reachable networks at each end came back out space-separated, while everywhere else — a trunk’s VLANs, for one — uses commas. A field that accepts anything and hands back a format nobody else uses teaches the wrong rule at every redraw. Reading stays wide: commas, semicolons, spaces and newlines all still parse, because somebody pasting from a carrier’s quote should not have to fix the separators by hand.

- **A site’s icon carries its state, and so does its box on the map.** Red if an incoherence names it, amber if a gap does, green if nothing does — the same three colours as the counters at the top of the panel, so it is one legend and not two. The border of the map box carries the same three colours — except for a site with no project linked, which stays neutral grey and claims nothing: it used to be dashed, and a dashed outline around a box full of text reads as a drawing glitch rather than as an absence. That site’s state is not lost, it is in the tooltip. ⚠️ Green reads «nothing reported about this site», and the tooltip says exactly that: it is not «all clear», because checks that could not run are counted separately and promoting them to an acquittal here is the lie this audit has avoided from the first line. One check is deliberately attributed to no site: a network that no site claims has no site to blame, and picking one would turn everybody’s problem into somebody’s fault.

- **The census of circuit types is now on screen, and it counts two different things.** The import already worked out, for every NetBox circuit type, which of our technologies it was — and then kept it to itself: the result box said how many lines and how many links had been added, and nothing about the decision the software had taken on its own. A decision nobody can see is a decision nobody can correct. It now lists every type it read, with how many circuits carried it and — where they produced any — how many inter-site links came out of it and what those links were read as.
  ⚠️ The two counts are deliberately not the same number, and the difference **is** the point: a technology is only ever decided for a link between two sites. On a WAN line the type is written verbatim into the service field and nobody chooses anything, so a type that produced only uplinks is listed with no technology beside it — printing «read as MPLS» next to twelve uplinks would be narrating a decision that was never taken, which is the same class of lie as a fallback presented as a measurement. One line under the list says why those have none, once, instead of repeating it on every row. Measured on the bench: a type whose slug is literally `mpls` but whose circuits both terminate on the carrier’s cloud is exactly that case, and it is the reason the two numbers are kept apart.
  A type that stayed «Other» says where its name went — it becomes the link’s description — because that is the row the reader may want to correct, and the dropdown is already on it. What decides is the **slug**, never the name, so a type renamed in NetBox keeps being recognised and a type named «MPLS» with no slug is still not judged by it.

- **A link’s technology can now be twelve things, not five.** IPsec, MPLS, VPLS, SD-WAN and direct link were the whole vocabulary, and five was too few: nearly everything a real DCIM archive holds landed in «Other» with a label — which is the software saying it does not know, in places where it did. It now also knows **GRE, WireGuard, OpenVPN, L2TP, VPWS, VXLAN and EVPN**. Every one of them is there because it corresponds to a value of NetBox’s own closed vocabularies — `tunnel.encapsulation` (8 values) and `l2vpn.type` (14) — and not because it sounds good: these are the words on the console of whoever configured the thing. The dropdown reads in families: tunnels, then carrier services, then what is neither, with «Other» at the end.
  What stays **out** is as deliberate as what came in: `ip-ip` and `pptp` (the first rare, the second dead), and the carrier Ethernet services (`epl`, `evpl`, `ep-lan`, `ep-tree`, `spb`) which are a family of their own — flattening them onto VPWS would be saying one thing for another. They keep arriving as «Other» carrying their NetBox label. The import’s translation table grew with the vocabulary: a GRE tunnel now arrives as GRE instead of as a label, and the four flavours of EVPN all arrive as EVPN — the control plane is what they name, and which transport sits under it is a question this model does not ask, the same loss already accepted between `ipsec-tunnel` and `ipsec-transport`.
  ⚠️ Widening the list uncovered a trap that had been there all along: the normaliser’s per-kind switch ended in `return null`, so a technology that was in the vocabulary but had no case **made the whole link disappear** — a valid row dropped in silence. It was caught by an existing test («reach reads the same on every kind»), which is exactly the kind of test that earns its keep. The switch now falls through to «a real technology with no fields of its own», because the unknown-kind guard sits upstream: adding a technology no longer means remembering a second place.

- **A circuit whose type is already one of our technologies comes in as that technology.** Every inter-site link born from a NetBox circuit used to arrive as «Other», including the ones whose type is literally MPLS or VPLS. The type’s *name* is free text of the instance, so reading it would work on an English archive and on no other — but its **slug** can simply *be* one of our technologies, and then nothing is being deduced: `mpls` does not resemble MPLS, `mpls` **is** `mpls`. That is identity, not translation, and asking somebody to declare that `mpls` means MPLS would be asking them to fill in a form to rewrite the same word. The comparison ignores dashes, underscores and case — NetBox builds the slug itself and turns «SD-WAN» into `sd-wan`, which is the same word wearing its generator’s punctuation.
  Everything else stays «Other» carrying the type’s name as its label: `dark-fiber`, `internet`, `fibra-spenta` are not technologies in our vocabulary, and rounding them to the nearest lookalike would be saying one thing for another. Those are corrected on the link’s own row, where the dropdown already is. A type with **no** slug is never judged by its name, even when that name reads «MPLS» — that single test is the vendor-neutral rule in one line. And a slug of `other` is not a declaration: it would be indistinguishable from nobody having said anything.
  The vocabulary is not copied into the mapper; it arrives from `lib/inter-site.js` through the UMD wrapper, and a test pins every technology of the model to being recognisable by identity — a second copy of that list is the duplicated definition this codebase has already seen diverge twelve times. The import also reports a **census**: which circuit types it met, how many circuits each, and what each one became, so a decision the software takes on its own is not invisible to whoever reads the result.

- **Two badges on the map never overlap.** Between the same two sites, parallel links fan apart by a fixed 34 px along the normal to their chord — and a constant does not look at the labels. On a near-vertical chord that normal is horizontal, so 34 px were separating «Collegamento diretto» from «IPsec»: they sat on top of each other, which is how it was reported. The fan step is now a *measurement*: the distance at which, along that normal, every pair of badges in the group stops touching — the same axis-separation test the ring radius already uses, not the sum-of-radii that comes to mind first and is wrong. Every pair is checked and not only the neighbours, divided by how many positions apart they sit, so a narrow badge in the middle cannot close two wide ones onto each other. It never goes BELOW the old constant — two arcs must stay distinct even when their labels are tiny — and it does not widen a fan that does not need it: with two sites side by side the normal is vertical, where 20-pixel-tall badges already clear. Without a ruler (first pass, or an export that does not measure) the measurements are zero and the constant stands: no width is invented for a font nobody knows.

- **A link that says «hub-and-spoke» between two sites of the same role is now caught.** The topology is written on the link’s row; the roles are written on the sites’ cards. They are two statements about the same arrangement, stored in two places, and nothing was comparing them — so a link declaring hub-and-spoke between two sites both declared *spoke*, or both declared *hub*, read as perfectly fine. Neither statement looks wrong on its own, which is exactly why it needed a check: this is the twelfth-time family of defect in this codebase, one definition living in two places. It lands among the **incoherences**, not the gaps: nothing is missing here, something is contradictory.
  Two things it deliberately does NOT do. It says nothing about `mesh`: a site can be a spoke of the carrier’s MPLS and sit inside a mesh of IPsec tunnels at the same time — two services, and the topology describes the service, not the site, so a contradiction found there would be an accusation against correct documentation. And **`standalone` never accuses**: it is the value the normaliser falls back to for any absent or unknown role, so «independent» and «nobody has written it yet» wear the same face — treating that fallback as a statement would greet every freshly created organisation with an incoherence. Those links are reported as not-checked, with the reason, like every other blind check here.
  ⚠️ The check made one line of the test fixture false: «a coherent model produces nothing, not even a not-checked». It was true only because nobody looked at the topology, and the reference organisation — the one whose comment says «Milan hub, Rome and Naples spokes» — never declared one. The fix was to make the fixture say what its own comment already said, not to lower the assertion. And the guard was made to fail on purpose once before being believed: with the comparison disabled, three of its tests go red.

- **«Shape» is called «Topology», and the field finally agrees with its own key.** Hub-and-spoke and mesh are *topologies* — the word every course and every vendor page uses, and the name the model has carried from the first line (`topology`). «Shape» was a plain-language stand-in for a term that does not need one: the two values it offers are jargon already, so spending the label on avoiding jargon bought nothing. **«Layout» was considered and rejected**: in this product layout is where the boxes are DRAWN — there is a module called exactly that, which decides the map's geometry — and one word for two ideas is how a codebase starts lying to itself.
- **And the dropdown is called «Technology», not «Kind».** «Kind» was ours, chosen at the keyboard; the word the field actually needed is the one used by whoever writes about wide-area networks, because the reader arrives here from their carrier’s quote and from a vendor’s page, not from our model. Italian technical writing calls MPLS, VPLS and SD-WAN *tecnologie* — so does NetBox, whose L2VPN `type` is documented as «the technology employed». **«Protocol» was rejected, and not on taste:** IPsec is a protocol, VPLS is a service, SD-WAN is an architecture and a direct link is a piece of glass — a label that fits one value in five and lies about the rest is worse than a vague one. The model key stays `kind`: it is the field’s *name*, and renaming a stored key to fix a label would migrate documents to change a word on a screen.
- **«Overlay» and «underlay» now say what they are.** Asked outright: the two fields on an SD-WAN link were a word over an empty box and a word over a list of checkboxes, and nothing on screen explained either. Both terms stay — Italian technical writing keeps them in English and explains them in prose, so translating them would have made the field *less* recognisable than the console the reader has open in the other window — and each now carries the sentence it was missing: the overlay is the LOGICAL network the SD-WAN builds on top of the lines, named as its own console names it; the underlay is the PHYSICAL lines that carry it, the ones the carrier invoices, which are the WAN uplinks on the tab next door. The overlay field also gained a placeholder, because an empty box teaches nothing about what belongs in it. The underlay field then went one step further: what it is for is now in the label itself — «Uplinks (the physical lines carrying it)» — and the note underneath is gone. It had been saying, in smaller type at the foot of a list of checkboxes, what the label above now says: a sentence read twice in two sizes reads as two different sentences, and the eye goes back looking for a difference that is not there. The jargon word survives where it is actually met for the first time — on the overlay field right beside it, which is where somebody who does not know it needs to be told.
- **And what it is called.** Third time the same lesson arrives, and the third source is again a real archive: in NetBox an L2 service and a tunnel have a `name` — «VPLS-MI-RM», «IPSEC-HQ-DR» — and that is what the link is called in a meeting and searched for on the device. It had nowhere to go: `phase1Name` is the name of phase 1 (an IPsec thing), `service` is the carrier's service, and `kindLabel` says the *nature* («GRE»), not the name. So an imported GRE arrived anonymous, and two tunnels between the same two sites became indistinguishable — including for whoever has to decide whether they are the same row. The name does not replace `kindLabel`: «GRE-LAB» is what it is called, «GRE» is what it is, and the map draws the second.
- **A link now says who sells it and under which circuit id, whatever its kind.** The same lesson as the ends above, found the same way — by reading a real NetBox. An MPLS, a VPLS, a dark fibre and even an SD-WAN underlay are all bought from an operator and have a code on the contract: it is *the* number dictated over the phone when the line is down, and it is the same question for every kind, so it is modelled once at the common level rather than per variant. Without it an inter-site circuit read from the DCIM entered having lost precisely the two things that identify it. On an IPsec over two internet lines both stay empty, and that is an answer, not a gap: they are declarations by construction — like the same two fields on a WAN uplink — so they carry no provenance envelope, because no device can read them.
- **Both ends of a link now name the device that holds them, whatever the kind.** The ends were modelled on IPsec links only, which is backwards: on an MPLS or a VPLS the end is the CE — a device in a rack, with ports on it — and it is precisely on the carrier links that you most need to know which box it is, because it is often not the one you configured. The ends are now common to every kind, the same reasoning that made `reach` one concept for all of them. An end holds *either* a reference to a node in the site's project *or* a name written by hand, never both: a name copied next to a reference is the same name written twice, and the two diverge the first time the node is renamed.
- **A WAN uplink carries public addresses, plural — because one was simply false.** A single public IP per uplink does not survive three ordinary cases: a business line almost always comes with a *routed block* (a /29, a /28) of which one address sits on the WAN interface and the rest serve 1:1 NAT publications; IPv6 is a second address (or a delegated prefix) on the *same* line, not a different uplink; and an HA pair exposes both nodes plus the shared VIP. With one field you had to pick one and stay silent about the others, which is documenting badly on purpose. Each entry is either an address (`203.0.113.10`, `2001:db8::1`) or a block (`203.0.113.8/29`), and the two are normalised down different paths on purpose — sending an address through the subnet canonicaliser would turn `203.0.113.10` into `203.0.113.0/24`, a different and much larger fact. The declared order is kept rather than sorted, because by convention the first entry is the interface's own address and reordering to tidy up would erase that convention silently. The coherence check now asks whether the list is empty, not whether it holds one: how many a line should have depends on the contract, and nobody here knows it.
- **A site is a box on the map, and its WAN line is inside it.** The uplinks were stubs pointing outward, away from the link, and the first question anyone asked of the map was «shouldn't the carrier be at the end of the link?». It is: an uplink belongs to a *site* (`wanUplink.siteId`), and the site is the end of the link — so it belongs inside the site's box, which is exactly what the model says. What could NOT be done is lay the carrier's name along the *edge*, as though that line carried that tunnel: nothing in the model declares it (the only place the association exists is an SD-WAN's `underlayUplinkIds`), and with two lines at one site nobody knows which one carries the IPsec — drawing it would be inventing with the face of a fact. The box now reads the site's name, each WAN line with its provider, service type and public addresses, and how many networks the site has; a site is opened by clicking it as before. Because a box has to fit its text and a pure module cannot know a font, the geometry takes an optional ruler: the browser draws once, measures the rendered lines with `getBBox()` and redraws with the real widths — no font constants copied out of the CSS, which would be one more definition to diverge at the next restyle. The same ruler is what the PDF export will pass, with its own measuring engine.
- **A link whose nature is none of the five can now say so in its own words.** The closed vocabulary — IPsec, MPLS, VPLS, SD-WAN, direct link — is deliberate: a link must not enter as something it is not. But a closed vocabulary that refuses real cases forces a lie (picking «direct link» for a carrier's radio bridge) or loses the row. There is now an `other` kind with a free-text name beside it. That is not the same as opening the field to arbitrary strings, which would have silently broken translations, icons and any future per-kind logic — and, worse, made «it is an IPsec» indistinguishable from «I don't know what to call it». With `other` the software knows that it does not know, and the words come from whoever documented it: the map draws «FWA point-to-point», not «Other». An unknown kind is still refused, exactly as before.
- **The SD-WAN underlay field can actually be edited.** It was a `<select multiple>`: you add and remove only with ctrl-click, an ordinary click wipes the selection, and with a single line it looked like a stuck box — «what is this field I can't change» was the first thing anyone asked of it. It is now one checkbox per line, one click on and one click off, each naming its provider and site, with a sentence saying what the field means and where the lines are described.
- **The coherence pane says each thing once.** Every row used to repeat its own heading — three rows under «Site networks that no link carries» each ending in «no link carries it» — so the part that actually varied was buried in the part that did not. Rows now carry only the subject; the sentence is the heading. Ids became names throughout (a link reads «Caci ↔ Aloys · VPLS», an uplink reads by its provider and site), and the checks that could not run no longer print the engine's own slugs at a human: `spokesWithoutHub — no-hub` is now the check's name and the reason in words. A reason the dictionary does not know yet is shown as it is rather than swallowed.
- **A project export no longer carries measurements — by construction, not by memory.** `sanitizePortableState` was a blocklist: it named what to remove, so a newly added measured field went out in exports until somebody remembered to add it to the list (which had already happened once). Measured against thirteen real projects, **41 fields were leaving that way** — among them `dhcpSources`, which carries the leases read from a DHCP server, meaning the names and MAC addresses of whoever was on that network, inside a file made to be sent to someone else. The export is now built from the field classification above. The old removals stay written out explicitly as a floor, so the export can never end up worse than it was even if the classification fails to load; and a port record that held nothing but measurements no longer leaves an empty shell behind. Nothing declared is dropped: verified on the live lab project, where 32 kinds of measured field were present and none reached the export while all 43 devices, 155 ports and 39 cables did.

- **A UPS from the catalogue arrives with its outlets.** The slim catalogue kept only network ports, so 53 UPS models carried none. They now come across with name and socket type, and the group is read from the name where the maker wrote it — 56% of UPS outlets, measured. What the name does not say stays blank: position is not evidence. Applying a model never costs you work: what you wrote on an outlet survives, and groups you declared are not renamed.
- **`--from-canonical` rebuilds the slim catalogue without the network**, reprojecting it from the canonical file on disk and leaving the manifest and diff untouched — the source did not change, only the projection.
- **The rack tells a port shut on purpose from one merely idle.** InfraNet read only whether a port has link, never whether someone turned it off. The two off-states now share a monochrome scale — near-black for shut by hand, dark grey for no link across three verifies — and the PDF and draw.io export print the same colours. A cable you drew over a shut port gets a "Port shut" badge: your word and the switch contradict each other. A status you declared keeps your colour, and the reading expires when the switch stops confirming it.
- **The Dashboard says out loud that it never looks at port access control.** 802.1X, MAB and port-security were missing from the list of dimensions the summary does not judge, with a "Security" lens right above it — and there silence reads as absolution. Declaring it beats reading half of it: "authorized" alone cannot tell an authenticated supplicant from a port forced open.
- **Wi-Fi from a DCIM arrives as Wi-Fi.** An 802.11 interface is an antenna, not a port: radios now come in as radios with band, standard and their BSSs, up to the eight the model allows, and the ninth is declared rather than dropped. The channel enters only when comparable — a wide channel names a block, not the primary 20 MHz one — and WPA2 goes in as the common case with a row saying so.
- **Virtual machines land on the host that runs them.** A cluster with exactly one imported member is unambiguous, so the VM goes there and the reading is declared as a reading; a cluster with two or more says nothing, so the VM stays out with the reason. Adapters bring MAC, VLAN and addresses, and megabytes become gigabytes out loud rather than inside a division.
- **IPAM roles can fill the four VLAN declarations that read them** — management, voice, guest, native — matched once per role, not once per VLAN. "Access - Wireless" is not the guest network: a rule reading the word "wireless" would have declared the whole corporate network a guest network.
- **Compare with the DCIM, without writing anything.** Rows show the document value and the DCIM value side by side. A device you added by hand is never reported as "gone from the DCIM" — that would accuse you of your own work — only declared fields are compared, and "different" is not "wrong": with no per-field timestamp nobody can say who changed it.

### Changed

- **One site, one project.** Step one is the site list, and an imported project records the slice of the DCIM it was born from — measured from the devices that really came in. The comparison re-reads exactly that slice: against a single-site project, comparing everything reported 181 new devices, all true and all useless. The instance address is deliberately not written into the document, which gets exported and passed around.
- **The import preview says each thing once.** Four ways of stating the same numbers, and two attention signals whose counts disagreed — the banner counted devices, the row counts decisions. Now the estimate is the only statement of numbers, losses join it as chips that jump to the row explaining them, and rows whose default is already right collapse to one line.
- **The manuals no longer cut a box in half at a page change.** 9 split blocks in Italian and 8 in English, measured on the rendered PDFs, now zero — at the cost of one page.

### Fixed

- **A UPS's outlets stopped being thrown away on import.** Nothing in the model was missing: six copies of `type === 'pdu'` across import, panels, rack and PDF kept them out. They now ask one predicate. A UPS you documented by hand keeps its front panel until it really has outlets. **The ATS stays out on purpose**: its two inputs are the point, and outlets without them would imply the redundancy had been captured.
- **Nine kinds of device could not come in from a DCIM, and one came in wrong.** Cameras, phones, PCs, displays, projectors, door controllers, sensors, tablets and KVMs had no entry, so eight different terminals produced eight copies of one generic — the *rack* generic, even with no rack, and the name-guessing rule filed a "KVM Switch" under switches.
- **Renaming a radio changes the labels that name it.** The name lived on the device and nothing that composes a label ever read it: six independent derivations each sliced the internal port id, so a radio printed "Pradio2" whatever you called it. One function answers now — including the names the DCIM import had already brought in and never shown.
- **A shut port, and a reading that never arrived, stop counting as evidence about the cable.** Both fed the down-streak that promotes an inferred cable to ghost and darkens a port. A decision is not an observation, and an unanswered poll is not a measurement: link state is now measured into its own field with three states — link, no link, **not measured** — and `unknown(4)`, which the RFC defines as "the agent cannot determine", no longer comes out amber.
- **"Replaced device" is no longer claimed from a reading that never happened.** A walk cut short left only the low ENTITY-MIB indices and the survivor was crowned, overwriting a good measurement and then being compared as if fresh. A measured identity now has three states — reconfirmed, **last known** (kept and dated), never measured — and whoever accuses asks the same rule and stays quiet unless it was reconfirmed.
- **A container prefix no longer counts as overlapping the networks inside it.** An IPAM plan is hierarchical on purpose: on a seven-network plan of the usual shape, eight conflicts, none real. Same for one space declared twice in two VRFs. Both are recognised and counted separately rather than silently dropped.
- **An address the import had worked out now reaches the port it belongs to.** The address is the socket's, not the device's. A router that used to arrive with one address now arrives with five, and what cannot fit — a second address, an IPv6, an interface with no port — is counted and declared.
- **"Next free IP" stops offering an address the plan has already booked.** IPAM reservations sit on no device but are not free either: they now come in, land on the network rather than on a device, and keep their own share of the occupancy bar.
- **A count taken across the whole archive no longer reads as a count of what you are importing.** Importing a site with six unattached addresses announced a hundred and eighty-six. Narrowing it properly costs one call per network; until that is worth paying, the sentence says what it actually counted.
- **Three fixes to one row of the import panel.** A raw `{total}` placeholder printed as-is, because a closed allow-list of context keys had never heard of it; an example dumped eighteen networks instead of three; and a row speaking for a whole reading counted itself as a single case — "One IP address stays out" over a hundred and eighty of them.
- **A tooltip showed a raw translation key.** "Trunk symmetry" was declared by the engine with no wording in either language, and the it/en parity gate could not see it: the key was absent from both, so the symmetry was perfect while the hole was too. A structural test now checks that every declared dimension carries its label and tooltip in both languages.
